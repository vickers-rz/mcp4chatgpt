# ChatGPT Extensions 接入计划

日期：2026-10-01。状态：已纳入路线图，尚未实现或完成客户端验收。

## 1. 决策与优先级

为 MCP4ChatGPT 增加 ChatGPT 内的交互界面，首先交付 Coding Task 只读对话面板。实施优先级排在现有可靠性验收之后，先完成 P3 尚缺的崩溃点和多进程故障注入验收，再启动面板原型。现有后端负责鉴权、文件权限、幂等、验证证据与 CAS 冲突处理；界面复用这些契约。

本计划是新增的客户端体验工作流，不重新编号原有 P0–P5 阶段，也不计入文档 28 的历史工期估算。原型通过后再评估后续阶段工作量。

官方参考：[Plugin Extensions](https://developers.openai.com/plugins/build/extensions)。该文档介绍对话面板、侧栏应用、文件查看与编辑、内容提及及上下文同步等入口。文档当前注明 Composer mentions 仅在桌面端提供，Web 上 Free/Go 的扩展支持仍标为即将提供；实施时须重新核对可用性，并记录实际客户端和账号测试结果。

## 2. 项目基础与接入缺口

当前可复用的基础：

- `workspace/coding_tasks.py` 和 `workspace/coding_task_tool_api.py`：任务、验证证据、成果发布及源码集成状态。
- `file_resources.py`：显式暴露文件的 `resource_link` 与资源读取。
- `tools.py`、`capability_catalog.py`：工具定义和 full/compact 能力发现。
- `server.py`：MCP 请求、认证及资源读取入口。

需要增加 UI 资源、工具的 UI 元数据、前端界面和客户端接入测试。现有文件资源支持不能作为 Extensions 已接入的证据。Python SDK、协议适配方式及前端依赖在实现前按官方规范核对并固定版本；本计划不要求重写现有 MCP 服务。

## 3. 分阶段范围

| 阶段 | 交付 | 启动条件 |
|---|---|---|
| E1 只读任务面板 | 在对话旁查看指定工作区中的 Coding Task、验证证据和日志 | 现有可靠性验收完成 |
| E2 内容提及 | 从输入框选择已授权的知识库资料或文件，并传入明确的资源身份 | E1 接入链路通过；目标客户端支持 |
| E3 文件查看器 | 为确有需要的报告、差异或专用数据格式提供查看界面 | 已确认文件类型和资源生命周期契约 |
| E4 侧栏与设置 | 汇总任务、知识库和工作区，提供产品偏好设置 | 前序功能稳定且有实际使用需求 |

文件编辑、发布、集成、重跑验证等写操作不属于 E1。后续增加时需单独定义权限、预期版本与操作结果核对流程。

## 4. E1：Coding Task 只读面板

用户在面板中指定工作区和任务，查看基线提交、候选提交、验证结果及其当前有效性、日志摘要、成果 ref 和源码集成状态。先支持明确的 `cwd` 与 `task_id` 查询；如需任务列表，再增加带 principal/workspace 范围过滤和分页的只读入口，不把进程内记录直接暴露给前端。

面板只调用受认证的只读工具，日志按范围授权并脱敏、限量返回。资源访问继续经过后端校验，前端持有的路径或 URI 不构成授权。读取失败、任务不存在、证据过期和网络断开需显示明确状态；刷新失败时标明上次读取时间，避免把旧结果呈现为当前结果。

接入顺序：

1. 注册最小 UI 资源和对话面板入口，验证目标客户端能加载界面。
2. 接入现有任务查询，完成身份传递、工作区过滤和日志读取。
3. 验证 full/compact 两种工具暴露模式。若客户端必须在 `tools/list` 中看到入口工具，应明确保留该入口并补兼容测试，不能假定隐藏工具可调用就代表界面可发现。
4. 在支持的情况下同步当前选中任务的上下文，验证用户所见任务与模型引用的任务一致；同步能力未验收前使用显式任务标识。

## 5. 验收与发布门槛

| 场景 | 通过条件 |
|---|---|
| 真实客户端加载 | 指定客户端中可打开面板，UI 资源与认证链路正常；记录版本、账号条件和证据 |
| 状态准确 | 基线、候选提交、验证是否过期、发布和集成状态与后端查询一致 |
| 隔离 | 不同 principal 或工作区不能读取彼此任务、日志及文件资源 |
| 只读边界 | 查看、切换、刷新和失败重试均不触发代码修改、命令执行、发布或集成 |
| 陈旧状态 | 验证后修改代码会在刷新后呈现失效；断网时明确标记旧数据 |
| 工具发现 | full/compact 下入口可发现；现有 capability 调用保持兼容 |
| 普通 MCP 客户端 | 不支持 Extensions 的客户端仍可使用原有工具接口 |
| 回退 | 可关闭 UI 入口和资源供应，继续使用原有工具；执行一次回退验证 |

协议和接口自动化测试通过后，必须在实际 ChatGPT 客户端完成上述验收。单元测试通过不等于侧栏、面板或内容提及已经可用。

## 6. 完成判定

E1 通过真实客户端验收后，更新本文件、文档索引及发布验收记录，列出已支持的客户端和已知限制。E2–E4 分别验收，不能因 E1 完成就宣称所有 Extensions 功能已支持。
